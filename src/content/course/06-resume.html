本课回答三个问题：/resume 恢复的到底是什么、怎样找到“消失”的旧会话、什么时候恢复旧会话反而不划算。

适合：经常把一个任务分成几天完成，或者同时维护多个分支、多个 Claude Code 会话的人。

📌 基于 Claude Code 官方文档与本机 Claude Code 2.1.220 核对至 2026 年 7 月。产品更新较快，具体行为以官方文档与 /release-notes 为准。

一句话结论

/resume 恢复的是一段可以继续追加的会话，不是把项目恢复到过去。

恢复：对话历史、工具调用与结果，以及部分会话状态
不恢复：过去的文件系统快照

所以续接旧会话后：

  • Claude 记得之前讨论过什么、读过什么、做过什么；
  • 磁盘上的代码仍然是当前状态；
  • 如果代码在这段时间被你、Git 或其他会话改过，Claude 需要重新读取才能看到最新版。

可以把它记成一句话：

resume 接着聊，rewind 才是往回退。

一、什么是 Claude Code 会话

一个会话，就是 Claude Code 持续保存的一段对话记录。

里面不只有你和 Claude 的文字，还包括：

  • 用户提示词；
  • Claude 的回答；
  • 工具调用；
  • 文件读取结果；
  • 命令输出；
  • 其他会话元数据。

这些内容会持续写入本机的 JSONL 文件：

~/.claude/projects/<project>/<session-id>.jsonl

默认保存约 30 天，可以通过 cleanupPeriodDays 调整。

不过不要直接依赖 JSONL 内部结构编写长期脚本，因为它可能随版本变化。如果想阅读或导出会话，优先使用：

/export

会话不是代码快照

会话记录里可能保存着“Claude 当时读到的文件内容”，但这不等于保存了一份可恢复的项目副本。

例如：

  1. 昨天 Claude 修改了 auth.ts；
  2. 今天你手动又改了这个文件；
  3. 然后恢复昨天的会话。

这时 Claude 能看到昨天的讨论和工具结果，但磁盘上仍然是今天的 auth.ts。

因此恢复重要会话后，最好先告诉 Claude：

先重新读取相关文件，并检查 git status 和 git diff，再继续修改。

二、resume 会恢复什么

当前版本恢复的不只是聊天文字，还包括一部分会话状态：

状态 恢复情况
对话历史、工具调用和结果 恢复
会话使用的模型 通常恢复，但显式 --model、环境变量、模型下线等情况会覆盖
自定义 agent 能找到原 agent 配置时恢复；找不到会警告并退回默认配置
权限模式 部分恢复；plan 和 bypassPermissions 不会自动恢复
活动 goal（目标） 恢复，但计时、轮次和 token 基线会重置
未过期的 scheduled tasks（定时任务） 恢复
后台 Bash 与 monitor 任务 不恢复
磁盘文件 保持当前状态，不回滚、不重放

如果会话此前已经执行过 /compact，或者恢复时选择了 Resume from summary，继续使用的是摘要状态，不保证早期内容逐字重新进入上下文。

还有一类内容需要重新提供。

如果原会话依赖这些启动参数：

  • --mcp-config
  • --settings
  • --plugin-dir
  • --fallback-model
  • --add-dir

恢复时通常需要再次传入。标准的 settings.json 和 settings.local.json 会在重新启动时从磁盘读取。

恢复会话不会恢复一份旧配置快照。通过 CLI 重新启动时，标准 settings 会从磁盘重新读取；特殊启动参数仍需重新传入。恢复后可以用 /context 和 /memory 检查实际加载状态。

三、五个常用入口怎么选

写法 适合情况
claude --continue 或 claude -c 直接继续当前目录最近一次会话
claude --resume 或 claude -r 打开会话选择器
claude --resume <名称或 ID> 直接恢复指定会话
claude --from-pr <PR号或 URL> 打开选择器，并按相关 PR 筛选
/resume 已经在 Claude Code 里，切换到另一段会话

最常用的是两个：

claude -c

适合“我只想继续刚才那件事”。

/resume

适合“我想从历史记录里找一件事”。

/continue 与 --continue 不完全是一回事

在当前版本中：

  • /continue 是 /resume 的斜杠命令别名；
  • claude --continue 是启动时使用的 CLI 参数。

也就是说：

/continue         → 在会话内打开恢复功能
claude --continue → 从 shell 继续当前目录最近一次会话

名字很像，但使用位置和默认行为不同。

如果当前目录没有可继续的会话，claude --continue 会提示：

No conversation found to continue

然后退出，不会偷偷创建一个空会话。

名称匹配有歧义时

claude --resume <名称>

遇到重名，会打开选择器，并把名称作为搜索条件。

而：

/resume <名称>

遇到重名会直接报错，需要改用不带参数的 /resume 手动选择。

四、会话选择器怎么用

运行：

claude --resume

或者在会话内运行：

/resume

就会打开会话选择器。

每一行通常会显示：

  • 会话名称或自动生成的标题；
  • 距离上次活动的时间；
  • Git 分支；
  • 会话文件大小；
  • 扩大范围后还会显示项目路径。

常用快捷键

按键 作用
↑ / ↓ 上下选择
Enter 恢复选中的会话
Space 预览会话内容；部分终端可用 Ctrl+V
Ctrl+R 重命名选中的会话
/ 或可打印字符 搜索会话，也可以粘贴 PR / MR 链接
Ctrl+W 显示当前仓库的所有 worktree
Ctrl+A 显示本机所有项目
Ctrl+B 只看当前 Git 分支
→ / ← 展开或折叠分组
Esc 退出搜索或选择器

如果从 claude --resume 选择器恢复失败，命令会退出并给出重试方式。

如果是在当前会话里的 /resume 选择器恢复失败，原会话仍然继续运行，不会被破坏。

五、会话没丢，可能只是作用域挡住了

Claude Code 会按项目目录保存会话。选择器默认主要显示：

当前 worktree

默认列表还可能包含从其他位置启动、但通过 /add-dir 加入了当前目录的会话。

如果没找到，再逐步扩大范围：

当前 worktree
      ↓ Ctrl+W
当前仓库的所有 worktree
      ↓ Ctrl+A
本机所有项目

为什么 worktree 里的会话看不见

同一个仓库的不同 worktree，是不同的绝对路径：

~/project          → main 分支会话
~/project-feature  → feature 分支会话

所以默认列表会分开显示。

在多 worktree 仓库里按 Ctrl+W，就能把同一仓库的会话一起列出来。

如果选择的是另一个 worktree 中的会话，Claude Code 可以直接恢复。

如果选择的是完全无关项目中的会话，它不会在错误目录里强行打开，而是把一条 cd 加恢复命令复制到剪贴板，让你切到正确目录再运行。

ID 恢复也有目录范围

通过 claude -p 或 Agent SDK 创建的会话不会出现在选择器里，但可以用 session ID 恢复：

claude --resume <session-id>

这条命令也应该从原会话所在项目目录，或同一仓库的 worktree 中运行。目录不匹配时，会提示找不到对应 session ID。

六、给重要会话起名字

会话一多，只看自动标题很难快速找到。

推荐在任务一开始就命名：

claude -n auth-refactor

会话进行中也可以改名：

/rename auth-refactor

不带参数时，/rename 会根据当前对话自动生成名称。

还可以在选择器中高亮会话，按 Ctrl+R 重命名。

自动标题不等于可恢复名称

新版 Claude Code 会为未命名的交互会话生成显示名称和 AI 标题，方便在列表中辨认。

但直接运行：

claude --resume <名称>

匹配的是你通过 --name、/rename 或选择器明确设置的名称，不要把自动显示标题当成稳定的恢复句柄。

推荐命名方式

feature-user-auth
bugfix-payment-webhook
refactor-api-routes
review-pr-142
docs-session-guide

名称最好满足三个条件：

  • 看得出任务类型；
  • 看得出具体对象；
  • 几周以后仍然能认出来。

避免使用 work、test、misc 或纯日期。

七、/resume、/clear、/compact 怎么选

这三个命令处理的是不同问题：

命令 做什么 适合情况
/resume 切换或恢复另一段已保存会话 回到之前的任务
/clear 保存当前对话，然后开启空上下文的新会话 开始一件不相关的新任务
/compact [说明] 把当前会话历史压缩成摘要 继续同一任务，但上下文太长

快速判断：

还是同一件事，只是对话太长  → /compact
准备开始完全不同的任务      → /clear
想回到昨天或之前的任务      → /resume

例如：

/compact 重点保留认证模块的决策、未完成事项和测试结果

比直接 /compact 更容易保住真正重要的信息。

超大会话恢复时的新选择

对于 Pro 或 Max 用户，如果一个会话：

  • 已经超过大约 100,000 tokens；
  • 并且闲置超过约一小时；

恢复时可能会先出现选择：

  • Resume from summary：先压缩，再继续；
  • Resume full session as-is：完整恢复；
  • Don't ask me again：以后默认完整恢复。

完整恢复保留细节更多，但后续每次请求携带的上下文也更大。

恢复摘要更省上下文，但摘要没保住的细节不会继续出现在模型的当前上下文里。

八、几个容易踩的坑

1. 恢复会话不等于恢复代码

想撤销文件改动，用第 5 课的 /rewind 或 Git。

想继续过去的讨论，才用 /resume。

2. 恢复后不要盲信旧文件内容

旧会话里的工具结果记录的是“当时看到的内容”。

如果文件已经变化，先让 Claude 重新读取关键文件，并查看：

git status
git diff

3. 同一个会话不要同时在两个终端继续

如果两个终端恢复同一个 session ID，消息可能交错写进同一份记录。

需要探索另一条路线时，用：

/branch

或者：

claude --continue --fork-session

4. 启动时的特殊参数不会全部自动回来

旧会话使用过 --mcp-config、--plugin-dir、--settings 或 --add-dir，恢复时记得重新提供。

5. 旧会话不一定值得恢复

如果任务已经改变、代码差异很大，或者旧会话充满无关岔路，重新开一个会话并写一句交接说明，往往更清晰：

上次已完成认证接口，当前请重新读取 auth/ 目录，从补充集成测试开始。

会话越长，携带的旧信息越多。真正应该恢复的是仍然有用的上下文，而不是所有历史。

动手练习

练习一：命名并恢复

  1. 在一个测试项目里运行：

    claude -n lesson-6-practice

  2. 让 Claude 读取一个文件并总结。

  3. 退出 Claude Code。

  4. 在同一目录运行：

    claude --resume lesson-6-practice

  5. 让它说明刚才读过什么。

  6. 再让它重新读取该文件，比较历史记录和当前磁盘内容。

练习二：扩大选择器范围

  1. 运行 /resume。
  2. 观察默认显示的会话。
  3. 如果项目有多个 worktree，按 Ctrl+W。
  4. 再按 Ctrl+A 查看本机所有项目。
  5. 用 Ctrl+B 只看当前分支。

练习的重点不是记住快捷键，而是建立一个判断：

先确认要恢复哪段对话，再确认当前磁盘是否仍然匹配那段对话。
