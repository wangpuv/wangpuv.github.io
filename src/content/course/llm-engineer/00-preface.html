这套教程整理自我的 LLM 学习笔记，一共 22 课：全程用 Ollama 跑本地模型，用 Python 自己写出 Agent 的调用和工具执行过程，无需购买云模型 API 额度。

这组笔记不是事后整理出来的正确答案。举一个我自己踩过的：我以为在比较不同的生成参数，日志打印的 top_p 也确实在变，但调用推理函数时漏掉了这个参数——三次跑的其实是同一组配置，那次对比等于没做。

这样的错误还有几个。它们和实验、修改过程一样，都来自我的 Learn LLM Engineer 学习记录，会原样保留，也是这套教程的起点。

学完以后，你能做什么

我们会逐步完成一个“最小 Agent”：它能查阅课程提供的本地资料，需要计算时调用工具，再根据结果回答并标明出处；工具出错、资料不足或次数用完时，明确结束。

模型根据任务和已经得到的工具结果提出下一步动作，Python 程序负责检查并执行。你能沿着代码看到：请求里放了什么、为什么调用这个工具、工具返回了什么，以及程序如何决定继续还是停止。

比如，从资料里查出前后两个时间点的数值、算出变化幅度，是一个便于核对的验收任务。更重要的收获是：以后要增加工具、更换资料或调整模型时，你知道该改哪一部分，以及怎样检查改动是否有效。

“最小”指任务范围明确、工具数量少、每一步都能看懂。第 5 课先做只会调用计算等简单工具的版本；查本地资料的能力到第 9 课才接入，第 13 课完成核心多步任务，后面继续完善运行与使用方式。

适合谁，为什么先自己写

如果你会写 Python，能理解函数、类、JSON 和基本 HTTP 请求，就可以开始。前面的课程从几十行的小脚本入手；后半程涉及 FastAPI、异步调用和服务访问控制，会补上本课需要的解释。没有后端经验的读者，可以先完成前 13 课，再继续学习接口与运行部分；Docker 作为可选运行路线。

主线会手写工具循环、状态管理和模块之间的连接，不依赖 LangChain，也不以 Dify、Coze 的可视化编排作为教学入口。目的是让你亲眼看到模型与程序如何配合，以后接触框架时，也能理解框架替你处理了什么。

我们仍会使用 Pydantic 做数据校验、FastAPI 提供接口等现成库，把时间花在需要理解的机制上。

四个阶段，逐步完善同一个 Agent

第一阶段：模型调用与工具执行｜第 1—5 课

从 Token、参数和等待时间开始，学习结构化输出、工具调用和消息组织。第 5 课沿用原笔记的 mini SDK 设计，将这些模块接成有执行上限的工具循环。这个版本还不会检索资料。

第二阶段：根据本地资料回答｜第 6—9 课

学习文本向量、文档切分和混合检索。第 9 课把检索接成 Agent 的工具，回答可以追溯到文段，资料不足时需要说明原因。

第三阶段：多步任务、记忆与失败处理｜第 10—13 课

比较边执行边决定与先计划后执行，记录任务状态，保存需要的信息，并处理超时与重试。第 13 课是核心 Agent 的阶段验收：能查资料、用工具、给出结果，也能在无法继续时结束。

第四阶段：把 Agent 做成可供他人使用的应用｜第 14—22 课

沿用笔记中的模型选择、日志、缓存、长上下文、服务化和评测经验，为同一个 Agent 增加接口与启动配置，并用小规模实验检查并发和访问限制。第 22 课用完整任务核对质量、失败处理、用量和耗时。

缓存、路由与压缩会通过对照实验说明适用条件，简单任务不必启用全部模块。完整的 22 课目录放在文末，方便按需要查看。

需要准备什么，代码在哪里

准备 Python、uv 和 Ollama。生成回答使用本地聊天模型，检索另配本地嵌入模型；每课发布时给出当次实测的型号与运行命令，模型需要先手动下载。

我目前使用的是 M1 Pro、16GB 统一内存的 Mac，本地跑 qwen3.5:9b、8K 上下文，发布前用它跑通过五个工具调用任务。这只是目前的实测配置，全系列的最低硬件要求尚未确定；Windows、Linux 和独立显卡配置还需要验证。每课发布时会说明实际使用的设备和模型。

完整代码、样例数据和运行说明会随第 1 课一起公开，届时在文末补入地址。

课程将按阶段更新，代码和实验验证后发布，暂不承诺固定频率。环境准备篇会说明依赖安装、Ollama 配置和第一次运行的方法。

先按说明运行一次，再改一个条件，观察程序为什么改变行为。希望这套教程最后留给你的，是一个能运行的 Agent，以及继续修改它的能力。

模型调用与工具执行｜第 1—5 课

第 1 课：发出一次请求后，怎样检查参数、用量和等待时间？

认识 Token，检查 temperature、top_p 是否真正传入请求，比较看到第一段内容和收到完整回答的等待时间。

第 2 课：让模型返回的数据，真正通过程序校验

检查 JSON 的字段、类型与取值，限制修复次数，并区分格式正确和事实正确。

第 3 课：模型提出工具调用后，程序怎样执行？

用工具注册表把模型提出的函数与参数交给 Python 执行，再把结果送回模型。

第 4 课：怎样组织任务要求、用户输入和工具结果？

整理 Prompt 的不同部分，让任务要求、待处理材料和工具返回值各有清楚的位置。

第 5 课：把模型调用和工具执行接起来，做出最小 Agent

沿用笔记中的小型 SDK，把调用、提示、执行和校验接成一个有次数上限的循环。

根据本地资料回答｜第 6—9 课

第 6 课：把文本变成向量，怎样找到相关资料？

从余弦相似度的小例子出发，理解文本向量如何用于检索。

第 7 课：长文档怎样切分，才不把答案切丢？

比较固定大小、按句子和递归切分，观察段落大小与重叠范围对答案完整性的影响。

第 8 课：向量检索加关键词，真的更好吗？

将关键词与向量分数按文档对齐，用固定问题检查混合检索是否带来改善。

第 9 课：把检索接成工具，让 Agent 根据资料回答

把查询、检索和上下文组装接入工具调用，让回答附带来源，资料不足时明确说明。

多步任务、记忆与失败处理｜第 10—13 课

第 10 课：先列计划还是边做边决定，Agent 怎样完成多步任务？

把 ReAct 与先计划后执行放在同一任务上比较，观察工具结果如何影响下一步。

第 11 课：Agent 做到了哪一步，什么时候应该停止？

用状态机区分执行中、完成、失败与次数耗尽，保存每一步得到的结果。

第 12 课：任务中的信息怎样保存，下次又怎样取回？

理解短期记录、历史摘要和长期记忆的分工，检查保存与检索是否保留了需要的信息。

第 13 课：Agent 执行失败后，怎样重试、恢复或结束？

处理超时、重试和本地备用模型，保留失败原因与部分结果。本课也是核心 Agent 的阶段验收：将查资料、调用工具、引用回答和失败结束串成完整任务。

把 Agent 做成可供他人使用的应用｜第 14—22 课

第 14 课：怎样为 Agent 选择本地模型，并限制任务用量？

理解模型路由的取舍，记录 Token、调用次数和耗时，为本地任务设置用量限制。

第 15 课：Agent 卡住或失败了，怎样从日志找到原因？

沿着同一次任务的模型与工具调用记录，定位失败发生在哪一步。

第 16 课：哪些结果可以缓存，什么时候必须重新执行？

学习嵌入缓存、检索缓存和回答缓存的区别，检查版本变化和相似问题误命中的情况。

第 17 课：任务记录越来越长，怎样保留关键事实？

观察何时需要压缩历史、一次压到什么程度，以及摘要和截断丢掉了哪些事实。

第 18 课：给 Agent 加上接口，返回执行进度和最终结果

用 FastAPI 调用同一个 Agent，把执行进度、最终回答或错误返回给调用者。

第 19 课：怎样配置和启动，让别人也能运行这个 Agent？

整理依赖、模型地址和资料路径，提供本地启动方式，并说明 Docker 路线的适用条件。

第 20 课：多个任务同时提交，Agent 怎样排队和处理？

用小规模并发实验观察等待时间、任务隔离和本地模型的处理能力。

第 21 课：谁能调用 Agent，它可以使用哪些工具和资料？

限制访问频率、输入大小和工具权限，检查外部资料中的指令是否会干扰执行。

第 22 课：交付前，用一组完整任务检查 Agent 是否合格

保留运行与打分分离的设计，检查任务完成、计算、引用、失败处理以及用量和耗时。
