本课回答三个问题：哪些内容应该跨会话保留、/memory 到底管理什么、Claude 改错代码后怎样安全退回。

适合：已经开始长期使用 Claude Code，希望减少重复解释，又敢于让它承担更大改动的人。

📌 基于 Claude Code 官方文档核对至 2026 年 7 月。产品更新较快，具体行为以官方文档与 /release-notes 为准。

一句话结论

这两个命令解决的是两种完全不同的状态问题：

/memory：管理“下次还要知道什么”
/rewind：处理“刚才改坏了怎么办”

前者让有价值的经验跨会话留下，后者给当前会话里的试错加一张安全网。

你可以把它们记成一句话：

记忆管下次，回滚管刚才。

一、Claude Code 有两套记忆系统

Claude Code 的持久记忆不是一个文件，而是两套并行机制：

CLAUDE.md 自动记忆
谁写 你或团队 Claude
主要内容 指令、规则、工作约定 工作中学到的经验和模式
典型例子 提交前跑测试、目录约定、编码规范 构建命令、调试心得、个人偏好
范围 组织、用户、项目或本地 按仓库隔离，同一仓库的 worktree 共享
加载方式 相关文件按层级加载 启动时加载 MEMORY.md 前 200 行或 25KB，主题文件按需读取

两者最重要的区别，不是“手动”和“自动”，而是责任归属。

CLAUDE.md 是你明确交给 Claude 的长期说明；自动记忆是 Claude 在工作中自行沉淀的经验。

因此：

  • 需要让整个团队共享的规则和工作约定，放进项目级 CLAUDE.md；
  • 只对你当前机器和工作习惯有用的经验，可以留在自动记忆；
  • 不能容忍偶尔失效的安全约束，不要只写成提示语，应使用权限、Hook 或其他强制机制。

二、/memory 是记忆控制面板

直接运行：

/memory

它没有需要记忆的参数，打开的是一个交互式面板。你可以在里面：

  • 查看用户级和项目级的 CLAUDE.md、CLAUDE.local.md 等记忆位置；
  • 创建或编辑尚不存在的记忆文件；
  • 打开自动记忆文件夹；
  • 开启或关闭自动记忆。

这里有一个容易混淆的细节：

/memory 展示的是可管理的记忆位置，其中可能包含尚未创建、也可能没有加载进当前会话的文件。

如果你要排查“为什么 Claude 没有看到这条规则”，应该运行：

/context

然后查看其中的 Memory files。实际加载情况以 /context 为准，/memory 更像编辑与管理入口。

怎么让 Claude 记住一件事

不需要特殊语法，直接用自然语言：

记住：这个项目统一使用 pnpm，不要运行 npm install。

Claude 会判断这条经验是否值得放进自动记忆。

如果你明确希望它成为项目规则，可以直接说：

把“提交前必须运行 npm test”加入项目的 CLAUDE.md。

一句实用判断是：

个人经验 → 自动记忆
团队规则 → 项目级 CLAUDE.md

三、CLAUDE.md 的四种作用范围

从范围最广到最具体，常见位置有四类：

  1. 组织级：由企业或 IT 部署的 managed CLAUDE.md。
  2. 用户级：~/.claude/CLAUDE.md，适用于你所有项目。
  3. 项目级：./CLAUDE.md 或 ./.claude/CLAUDE.md，适合随 Git 分享给团队。
  4. 本地级：./CLAUDE.local.md，只放个人的项目偏好，通常加入 .gitignore。

Claude Code 会从较广的范围读到较具体的范围。同一目录中，CLAUDE.local.md 排在 CLAUDE.md 之后。

但不要把这个顺序理解成严格的配置覆盖：

这些内容最终会一起进入上下文。规则互相矛盾时，Claude 仍可能选择不一致。

比起依赖“后加载的覆盖前面的”，更稳的做法是定期清理冲突，让每条规则明确、具体、可验证。

还有一个细节：

  • 当前工作目录及其上层的相关文件，会在会话启动时加载；
  • 子目录里的 CLAUDE.md，通常等 Claude 读取该子目录文件时再按需加载。

所以大型仓库不必把所有规则都塞进根目录，可以把局部约定放在对应目录，或者拆进 .claude/rules/。

四、自动记忆怎样保存，又为什么会“忘”

自动记忆默认开启，需要 Claude Code 2.1.59 或更高版本。

默认目录是：

~/.claude/projects/<project>/memory/

同一个 Git 仓库的不同子目录和 worktree 会共享这套自动记忆。它只保存在本机，不进入 Git，也不会自动同步到另一台机器或云环境。

目录通常类似这样：

memory/
├── MEMORY.md
├── debugging.md
├── api-conventions.md
└── ...

其中：

  • MEMORY.md 是精简索引，每次会话都会加载；
  • debugging.md 等主题文件保存细节，需要时再读取；
  • 默认路径可以通过 autoMemoryDirectory 调整。

200 行 / 25KB 上限

每次会话启动时，只加载 MEMORY.md 的前 200 行或前 25KB，以先达到的限制为准。

当前版本会在文件接近上限时提醒 Claude 精简；如果写入后超限，写入仍会成功，但会返回提示要求重写索引。下一次加载时，超过上限的部分不会进入上下文。

所以维护自动记忆时，重点不是“多记”，而是：

  • MEMORY.md 每条只保留一句索引；
  • 详细过程移进主题文件；
  • 合并重复内容；
  • 删除已经过时或被证明错误的经验。

可以隔一段时间运行 /memory，打开自动记忆文件夹做一次审计。

注意： 主会话的自动记忆不会自动注入普通子代理。委派任务时真正不可缺少的规则，应放进 CLAUDE.md，或者在任务里明确写出来。

五、/rewind：当前会话的存档与读档

打开方式有两个：

/rewind

或者在输入框为空时，连续按两次 Esc。

如果输入框里已经有文字，双击 Esc 会先清空输入，而不是打开回滚菜单。文字仍保留在输入历史里，之后按 Up 可以找回。

/checkpoint 和 /undo 是 /rewind 的别名。

检查点是怎样产生的

Claude Code 会在每一条用户提示词处创建检查点，并记录主会话中文件编辑工具产生的改动。

当前版本会保留一个会话最近 100 个检查点的文件快照。检查点和会话一起保存，因此退出后重新 /resume，仍然可以回到之前的节点。

会话和检查点默认约 30 天后清理，可以通过 cleanupPeriodDays 调整。

六、回滚菜单的六种动作

先选择一条历史提示词，再选择要执行的动作：

动作 会发生什么 适合情况
Restore code and conversation 代码和对话一起退回 实现方向整体错了
Restore conversation 只退对话，保留当前代码 文件没问题，但对话已经跑偏
Restore code 只退代码，保留当前对话 需要撤销文件改动，但还想保留讨论
Summarize from here 压缩选中节点及其后的对话 丢掉一段岔路，保留前面上下文
Summarize up to here 压缩选中节点之前的对话 保留最近讨论，压缩早期铺垫
Never mind 取消操作 只是进来看看

两个代码恢复选项只会在该节点之后存在可恢复的文件改动时出现。

Summarize from here 和 Summarize up to here 不会修改文件。它们像“可以选择压缩哪一侧”的精准版 /compact，原始消息仍保留在会话记录里。

如果你恢复了对话，或者选择了 Summarize from here，当时的原始提示词会重新回填到输入框，方便修改后再次发送。

七、哪些改动不能被 /rewind 撤销

这是使用检查点时最重要的安全边界。

/rewind 主要追踪当前主会话里，由 Claude 文件编辑工具产生的改动。下面这些内容通常不在恢复范围内：

  • Bash 命令改动的文件，例如 rm、mv、cp 或重定向写文件；
  • 后台子代理写入的改动，包括后台运行的 /code-review --fix；
  • 你手动修改的文件；
  • 其他并发会话修改的文件；
  • 软链接或硬链接指向的文件；
  • 已经产生的数据库、API、部署等外部副作用。

所以运行 --fix、批量脚本或危险 Shell 命令之前，应该先看 git status 和 git diff；重要状态先 commit 或 stash，需要探索另一条路线时再创建分支。

/rewind 和 Git 的分工

/rewind Git
定位 当前会话的快速撤销 长期版本历史
粒度 每条提示词附近的检查点 每次 commit
适合 试错、跑偏、临时恢复 跨会话、协作、分享与永久记录

它们不是替代关系：

检查点是本地撤销，Git 才是永久历史。

八、回滚时怎么选

记住这张快速选择清单：

只有代码错了      → Restore code
只有对话跑偏      → Restore conversation
代码和对话都错了  → Restore code and conversation
只想释放上下文    → Summarize
想尝试另一条路线  → /branch

如果希望从命令行复制当前会话并另开路线，也可以使用：

claude --continue --fork-session

分支会话适合探索平行方案；/rewind 更适合在原会话中恢复状态。

动手练习

练习一：审计记忆

  1. 运行 claude --version，确认版本不低于 2.1.59。
  2. 运行 /memory，打开自动记忆文件夹。
  3. 找出一条过时、重复或过于冗长的记录。
  4. 删除它，或者把细节移动到一个主题文件。
  5. 再运行 /context，观察当前会话实际加载了哪些记忆文件。

练习二：只回滚代码

  1. 让 Claude 修改一个测试文件里的一句话。
  2. 输入框保持为空，连续按两次 Esc。
  3. 选择改动之前的提示词。
  4. 选择 Restore code。
  5. 确认代码恢复了，但对话仍然保留。

练习的重点不是学会“撤销”，而是建立两种习惯：

值得复用的经验及时沉淀，风险较大的改动先确认能不能安全退回。
