核心心法：/context 看 → /compact 压 → /clear 清。

一句话记法：先看清楚，接着做就压，换事就清。

适合：已经开始用 Claude Code，想避免长对话越来越慢、越来越容易漏掉约定的人。

📌 基于 Claude Code 官方文档核对至 2026 年 6 月。产品更新较快，个别细节以官方文档与 /release-notes 为准。

为什么要管上下文

模型有一个有限的上下文窗口（它的「工作台 / 短期记忆」）。它会被这些东西占满：系统提示词、CLAUDE.md、MCP 工具、子代理配置、对话历史，以及文件内容和工具输出。其中，读入大文件最容易迅速占满空间。

填满的三个后果，由轻到重是：

  1. 变笨：窗口越满，越容易忽略中间内容（context rot，上下文腐烂），你会感觉它「忘了刚说好的规则」。
  2. 变贵 / 变慢：每轮都要重新处理整个上下文。
  3. 撞墙：上下文满了，就必须先处理才能继续。

真正的高手靠预防：别让它读整个大文件；一个任务用一段对话；处理完的日志别一直留着。做到这三点，三件套的使用频率会大大下降。

1. /context [all] —— 看

这个命令会把当前上下文占用画成彩色网格，并在右侧给出分类明细。它只看不改。

怎么读最有效？ 先看顶部的大局百分比，再把右侧明细分成两类：

  • 固定开销：开局就在，与聊不聊无关，包括 System prompt、System tools、Custom agents、Memory files、Skills。精瘦才健康。
  • 对话本身：也就是 Messages。这通常是占用的大头，也是 /compact、/clear 将来要处理的部分。

两个细节：

  • MCP 工具按需加载（loaded on-demand），平时不计入占用，可以放心连接。
  • Skills / 插件只加载「目录摘要」，每个通常只有几十到一百多 token；真正触发时才展开完整内容，所以装得多，固定成本也很低。

经验阈值，可以先用这套粗略心理标尺：

占用 怎么做
< 50% 放心干，无视它
50%–70% 留个心眼，看看有没有大文件赖着
70%+ 该决策：没干完就压，换题就清
接近上限 会触发自动压缩，但通常已经偏晚

2. /compact [指令] —— 压缩上下文

这个命令会把目前整段对话替换成一份摘要来腾空间。压缩之后，Claude 从摘要继续，不再看原始的逐字对话；没有写进摘要的细节，在它的视野里就消失了。

所以，/compact 是有损压缩。

它的心智模型是：给「失忆的未来 Claude」写一张交接 note。

你可以问自己：

如果换一个没参与过的新同事接手，只给他一张纸，上面必须写什么，他才能不出岔子？

该让它保留的内容，按价值排序是：

  1. 做过的决定 + 为什么。理由要一起留，否则以后很可能重新纠结。
  2. 约束 / 规则 / 约定，例如命名规范、schema、API 契约、「X 别动」。
  3. 当前进度：做完了什么、正在做什么、下一步是什么。
  4. 精确标识符：具体文件路径、函数名、字段名、报错原文。摘要很容易把它们模糊化。
  5. 还没解决的开放问题。

指令怎么写？ 点名具体产物，不要只说「保留重点」，因为这等于没有给靶子。

# 几乎没用
/compact 保留重要内容

# 更好的写法：给明确靶子
/compact 保留 users/sessions 两张表的 schema 和命名规范；
还没实现的三个端点（login/refresh/logout）；
“错误统一用 ApiError 包装”这条约定。探索过程和日志可丢。

一个进阶招法： 会反复用、长期需要的东西，例如 schema 和稳定约定，与其塞进一份有损摘要，不如先写进 CLAUDE.md，再执行 /clear，让它进入「每段对话都自动加载」的持久位置。

两者的分工是：

  • 长期约定 → CLAUDE.md（永久）
  • 临时过程状态 → /compact（临时）

摘要是有损的，别把它当作精确事实来源。压完以后，可以顺手让 Claude「列一下我们定了哪些约定」，发现漏项就趁记得立刻补上。

3. /clear [名称] —— 清

这个命令会开一段全新的空对话，相当于把桌面一扫而空。它的别名是 /new、/reset，就是其他工具里的「新建对话 / New Chat」。

旧对话并没有被删除，之后仍然可以通过 /resume 找回来，这会在第 6 课详细讲。

什么时候用？

  • 换一件不相关的事：这是占九成的用途。不要让上一件事的上下文污染下一件事。
  • 任务做完了，而且上下文又满又乱：清空重来，比压出一份臃肿摘要更干净。
  • 想让它「换个脑子」：Claude 钻进某个思路出不来时，清空往往比反复掰扯更有效。

什么时候不要用？

任务还没干完，而且仍然需要前面的来龙去脉。这时应该用 /compact，或者干脆继续聊。

/clear 与「退出重开」不同：重进后如果提示压缩并继续上次的内容，那是续旧（continue）；/clear 是主动开一段全新的、什么都不带的对话。换题时敲 /clear，比退出重启省事。

参数速查

三个命令都能跟参数，而且参数都可以省略：

命令 参数 类型
/context [all] all 固定关键词，用来展开完整明细
/compact [指令] 任意文本 自由文本，说明重点保留什么
/clear [名称] 名称 可选，用来给新会话命名

实操建议

  • 如果你习惯「退出重进、点同意压缩」，那就是 compact 的自动档。对多数日常场景完全够用，不必刻意改变。
  • 手动 /compact 并补充指令是进阶可选项，留给「精细长任务已经明显在丢关键细节」时再用。没有遇到，就先当它不存在。
  • 不用自己记该保留什么。可以让 Claude 帮你 recap：「我们定了哪些关键决定和约定？」长期要留的，再让它写进 CLAUDE.md。
  • 忘了细节但没有出事，往往说明那些细节本来就不关键，不必焦虑。
  • 唯一值得养成、而且几乎不花时间的习惯：换不相关的活之前，顺手 /clear。

动手练习

在你当前的一段 Claude Code 长对话里，按顺序做一次：

  1. 输入 /context，看清固定开销和 Messages 各占多少。
  2. 如果任务还没结束，先让 Claude 列出关键决定、约束、当前进度和开放问题。
  3. 用一条带明确保留项的 /compact 压缩，再让它复述一次约定，检查是否遗漏。
  4. 当前任务结束后，用 /clear 开一段新对话，再开始下一件不相关的事。

你真正要形成的不是「经常敲命令」，而是一个判断习惯：先看清楚；同一件事继续做就压；换一件事就清。
