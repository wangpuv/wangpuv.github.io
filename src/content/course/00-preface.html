如果你已经装好了 Claude Code，也成功让它改过几次代码，大概很快就会遇到一个问题：

会用，不等于用对。

你知道可以让它读代码、写功能、跑测试，却未必知道：

  • CLAUDE.md 应该写什么，为什么写得太多反而会让 Claude 更容易忽略重点；
  • 上下文快满时，应该继续、压缩，还是直接开一段新会话；
  • 什么任务适合交给子代理，什么任务派出去只会多花 token；
  • 自动接受编辑、自动模式和计划模式，分别放开了什么，又拦住了什么；
  • 怎样让 Claude 不只“把代码写出来”，还真正运行、验证，并持续工作到目标达成。

这些问题很少能靠记住几个命令解决。

真正决定 Claude Code 好不好用的，是你有没有建立一套正确的心智模型：什么时候用、为什么用、边界在哪里，以及出了问题怎么退回来。

这也是我整理这套教程的原因。

为什么还要再写一套 Claude Code 教程

现在关于 Claude Code 的中文内容已经不少，但我在学习和使用过程中反复遇到两个问题。

第一个问题是：很多内容只罗列命令，不解释命令之间的关系。

你会看到一长串 /compact、/clear、/resume、/rewind，每个解释一句，看完好像都懂；真正遇到长任务时，还是不知道该选哪一个。

第二个问题是：产品更新太快，旧说法很容易被继续转抄。

命令的参数、别名、可用套餐和具体行为都可能变化。文章写得越确定，一旦没有标注核对时间，反而越容易误导后来的人。

所以，这套教程不按命令字母表展开，也不追求把所有功能一股脑塞给你。它采用三个原则：

  1. 按使用频率组织：先学每天都会碰到的地基，再学提速和自动化。
  2. 先讲心智模型：不仅告诉你“怎么敲”，还解释“为什么这样选”。
  3. 发布前重新核对：以官方文档和当前版本的真实行为为准；版本敏感的内容会明确标注。

我的目标不是让你背下一本说明书，而是让你在真实项目里遇到问题时，知道应该从哪个抽屉里拿工具。

17 课会讲什么

整套教程分成三个阶段，外加一份随用随查的命令附录。

第一阶段：先把地基打稳

第 1—6 课解决的是 Claude Code 最常见、也最容易被低估的问题：

  • 怎样写一份 Claude 真正会遵守的 CLAUDE.md；
  • 怎样查看、压缩和清理上下文；
  • 怎样选择模型，并在动手前先进入计划模式；
  • 怎样审查代码，而不是让模型草草给自己盖章；
  • 怎样管理长期记忆，以及在改坏代码后回到检查点；
  • 怎样恢复旧会话，又不把文件状态和对话状态混为一谈。

这一阶段的目标不是“知道更多命令”，而是让 Claude 在项目里记得住、想得清、跑偏后回得来。

第二阶段：让它变得可控

第 7—11 课进入项目配置和日常控制：

  • 子代理与 MCP 各自解决什么问题；
  • 权限规则、自动接受编辑和自动模式的真实边界；
  • 怎样在推理强度、速度和成本之间做选择；
  • 怎样检查改动、用量与当前运行状态；
  • 怎样使用帮助、技能列表和侧问工具，减少主上下文污染。

这一阶段最重要的不是“放开更多权限”，而是学会用规则画边界，再在边界内提速。

第三阶段：从单线程走向并行和自动化

第 12—17 课会处理更进阶的工作流：

  • 什么样的大改动适合拆成并行任务；
  • 后台、分叉、分支和任务面板之间有什么区别；
  • 怎样让 Claude 真正运行并验证应用，而不只看测试是否变绿；
  • 怎样用循环和目标机制持续推进任务；
  • 怎样使用云端深度审查与规划；
  • 怎样理解动态工作流、多代理研究和自动编排。

这一阶段的目标是让 Claude 从“你问一句，它做一步”，逐渐变成一个能够并行协作、持续验证、在明确边界内自动推进的工程伙伴。

最后还有一份命令速查表

远程控制、GitHub、Slack、Chrome、IDE、诊断、界面、账户和计费等低频命令，不值得占用完整课时。

它们会集中放在附录里。需要时查，不需要背。

这套教程适合谁

它最适合这样的读者：

  • 已经安装 Claude Code，并跑通过几次真实对话；
  • 不满足于“让 AI 帮我写一段代码”，希望把它放进完整开发流程；
  • 经常遇到上下文变乱、权限弹窗太多、改动不敢放手等问题；
  • 想使用子代理、并行和自动化，但不愿拿安全与成本碰运气。

如果你还没有安装 Claude Code，这套教程也可以先收藏，但它不是从注册、安装和登录开始的零基础手册。

我们从“已经能跑起来”出发，目标是走到“用得快、用得省、用得稳，也敢让它自动跑”。

我会怎么更新

这套教程共 17 课，计划每两天更新一课。

每一课都会尽量保持同样的结构：

  • 先回答一个真实问题；
  • 给出一句话心智模型；
  • 讲清命令之间的边界；
  • 用实际场景说明怎么选；
  • 列出容易踩的坑；
  • 最后留一个可以马上动手的练习。

Claude Code 仍在快速更新。每篇文章发布前，我都会再次核对官方文档与当前版本；如果某个功能存在版本、套餐或平台差异，也会直接写明，而不是假装它对所有人都一样。

因此，请把这套教程当成一张持续校准的地图，而不是刻在石头上的命令百科。

怎样跟着学，效果最好

我的建议很简单：

不要只收藏，至少把每课最后的练习做一遍。

Claude Code 是一个交互式工具。许多边界只看文字很容易觉得“我懂了”，真正敲一次、看一次终端反馈，才会变成自己的判断。

也不用追求一次记住全部命令。先掌握前三课，很多日常使用问题就会明显减少；等地基稳定，再进入权限、子代理与自动化。

学习顺序本身，就是使用优先级。
